# Этап 0. Организационная подготовка проекта

## Что сделал

1. Создал структуру Django-проекта: `manage.py`, пакет настроек `megano/`
   (`settings.py`, `urls.py`, `wsgi.py`, `asgi.py`).
2. Вынес конфигурацию в переменные окружения через файл `.env`
   (`SECRET_KEY`, `DJANGO_DEBUG`, `ALLOWED_HOSTS`, имя файла БД), загрузку
   сделал через пакет `python-dotenv`. В репозиторий добавил только
   `.env.example` с примером значений, сам `.env` — в `.gitignore`.
3. Подключил в проект готовый пакет `frontend` из `diploma-frontend/`
   (Vue3-фронтенд без сборки, шаблоны через `TemplateView`, статика и
   JS-логика — в комплекте): собрал и установил пакет в виртуальное
   окружение, добавил в `INSTALLED_APPS`, подключил его маршруты в
   `megano/urls.py`.
4. Инициализировал git-репозиторий проекта, сделал первый коммит со
   скелетом (314 файлов — код фронтенда и backend-скелет).
5. Выполнил миграцию стандартных таблиц Django (`migrate`), локально
   запустил сервер разработки, вживую в браузере проверил, что стартовая
   страница магазина открывается, статика (CSS, изображения, JS) отдаётся
   корректно.

## Для чего

Этим этапом подготовил рабочий каркас проекта, на котором дальше строю
всю бизнес-логику (модели, API, админку). Без этого шага не смог бы
проверять backend вживую и переходить к следующим этапам.

## Почему именно так

- **Конфигурацию вынес через `.env`, а не хардкодом в `settings.py`** —
  так требует ТЗ: проект должен быть «легкопереносимым», разворачиваться
  через `git clone` → правку `.env` → `migrate` → `runserver`, без
  необходимости менять код.
- **Оставил минимальный `requirements.txt` на этом этапе** (`Django`,
  `python-dotenv`) — библиотеки добавляю по мере реальной необходимости
  конкретного этапа, а не заранее «про запас».
- **Пакет `frontend` подключил строго по инструкции из его собственного
  `README.md`** (сборка `sdist` → `pip install` → `INSTALLED_APPS` →
  `include` в `urls.py`) — это готовая вёрстка, которую нельзя менять по
  условиям ТЗ, поэтому подключил его так, как задумано авторами пакета,
  без модификаций.
- **Завёл отдельный, независимый от `python_django` git-репозиторий** —
  так прямо требует ТЗ («для проекта должен использоваться отдельный
  git-репозиторий»). Репозиторий на gitlab.skillbox.ru у меня пока закрыт
  (видимо, откроется после сдачи практической работы 20.7 и прохождения
  тестирования по курсу), поэтому пока работаю с локальным git; удалённый
  `origin` подключу, как только доступ откроется.
