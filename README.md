# Megano — итоговый дипломный проект (интернет-магазин)

## Развёртывание

1. `git clone <ссылка на репозиторий>` — команды ниже выполняются из корня склонированного репозитория
2. Скопировать `.env.example` в `.env` и заполнить значения
3. Создать и активировать виртуальное окружение, затем **из корня репозитория** установить зависимости и пакет `frontend`: `pip install -r requirements.txt` (путь до архива фронтенда в `requirements.txt` — относительный, из другой директории установка не найдёт файл)
4. `python manage.py migrate`
5. `python manage.py seed_demo` — наполняет базу демо-данными (категории, товары, баннеры и т.д.) и генерирует для них картинки-заглушки; команда идемпотентна, её можно безопасно запускать повторно. Без этого шага каталог и главная страница будут пустыми — картинки товаров и категорий не хранятся в git (см. `.gitignore`, `media/`), а создаются этой командой на лету
6. Запустить Redis — брокер очереди задач для «фиктивного сервиса оплаты» (ТЗ: «процесс» оплаты добавляется в очередь): `docker compose up -d redis` (нужен установленный и запущенный Docker Desktop). Адрес брокера задаётся переменной `CELERY_BROKER_URL` в `.env` (по умолчанию — `redis://localhost:6379/0`, подходит для Redis из docker-compose выше)
7. Запустить Celery-воркер — обрабатывает задачи из очереди (в отдельном терминале, с активным виртуальным окружением, из корня репозитория): `celery -A megano worker --loglevel=info --pool=solo` (флаг `--pool=solo` обязателен на Windows — стандартный пул воркера там не работает)
8. `python manage.py runserver 0.0.0.0:8000`

Раздача статики (CSS/JS/картинки фронтенда) и медиафайлов настроена так, что работает сразу после `runserver`, независимо от значения `DJANGO_DEBUG` — `collectstatic` и отдельный веб-сервер под статику не требуются.

Раздел будет дополняться по ходу разработки.
